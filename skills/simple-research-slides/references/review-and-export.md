# 审核与导出

## 先审理解，再看页面

给审核者完整的页标题、页上文字和逐页讲稿，以及解释事实所需的最少上下文。
不要自动发送原始私有文件或整段会话。用户指定外部审核时实际调用指定模型；
无法调用时报告实际问题，不能模拟它的意见或悄悄换模型。

可复制的审核 prompt：

```text
请以刚接触这个研究方向的本科生视角严格审核这份科研汇报。
只聚焦审核，给出具体、可修改的问题。

检查：
1. 每页能否说清在回答什么问题，前后是否连贯。
2. 专业词首次出现是否有简短解释，听众能否读懂图。
3. 标题、图、图注和讲稿是否讲的是同一个例子和比较。
4. 数据单位、分母、比较对象及筛选/测试角色是否清楚。
5. 结论是否由证据支持，相关性、复现和因果是否区分。
6. 请教问题是否具体，能否帮助决定下一步。
7. 删除空话、重复免责声明和术语堆叠，同时保留改变判断的事实。

输出“通过”或“需修改”。需要修改时按页码指出问题、原因及修改建议，
将导致误解的内容列为必须修改，纯粹的措辞偏好单列。
仅凭文字无法判断的视觉问题列为“需看实际页面”。
```

把用户新指出的问题补入上下文，保持检查标准不变。先修正有依据的必须修改项；
若意见误解了材料，提供必要事实再复核。记录审核工具、请求/返回模型、日期、
草稿指纹和意见。文字有实质修改时重新审核最终稿，不把“已送审”说成“已通过”。
一次通过只说明这轮检查的结果，交付仍需下面的页面检查。

## 页面检查

1. 渲染实际交付版本的全部页。检查标题、正文、图例、坐标、误差线、数值标签、
   图注、页脚、中文字体及所有备用页。缩放到接近投屏大小，看图中文字是否读得清。
2. 检查 PNG 与 PDF，尤其是打印样式、隐藏导航、图片加载、换行和页数。
   修订后重新导出受影响页，最终版本再核对整套页面。
3. 对 PPTX 核对可编辑文字、备注和必要的原生图表/表格。生成库检查与原生应用
   打开是不同证据，按实际完成情况记录。不为通过检查删掉关键科学内容。
4. 保留一个简短交付记录：版本、页数、主讲/讨论时长、来源版本、文字审核、
   渲染检查以及影响使用的待解决问题。

## 配套 HTML 模板

`assets/starter.html` 使用1920×1080逻辑画布，有五页可改的版式：封面、数据、
方法、结果、请教。模板中的点和数字全部是构造示意。复制后修改文本、图和讲稿；
保留 `.slide`、`data-title` 和 `window.simpleSlides` 接口即可使用导出脚本。

元素通过 `data-qa` 标记。把正文、标题、图注和图表区域加上该标记；嵌套区域
只标记独立的外层或子元素，避免重复包围盒误报。脚本检查标记文字的滚动溢出、
标记元素越界及非嵌套元素相交，不读取图像里的字体或数据。

在技能目录执行：

```bash
node scripts/render_slides.cjs assets/starter.html --out-dir build/starter --strict
```

可以沿用父项目已有的 `PLAYWRIGHT_MODULE`、`CHROMIUM_PATH` 环境变量。
`CHROMIUM_NO_SANDBOX=1` 只在运行环境确实要求时使用；脚本不会安装浏览器，
也不会改变机器设置。所需依赖是已有的 Node、Playwright 与 Chromium。

输出 `slides.pdf`、逐页 PNG、`speaker-notes.md` 和 `render-check.json`。
脚本阻止 HTTP/HTTPS 请求，使用本地或内嵌素材；外链图片和字体应先按授权准备。
页数、视口缩放、键盘翻页、讲稿开关、字体与图片加载、打印布局均单独记录。
`--strict` 遇到文字重叠等需复核项也返回非零状态。

自动检查发现问题时返回非零，并保留报告。它不会自动缩字、删图或隐藏失败。
包围盒检测只是辅助，不能证明图中文字、图形遮挡、字体替代或科学结论正确。
人工看完实际输出后才能记录已做视觉检查。

本模板用于 HTML/PDF。需要可编辑 PPTX 时，用任务环境中合适的演示工具
生成并保留文本、讲稿及图表数据；不要把 PDF 或整页截图改名成 PPTX。
