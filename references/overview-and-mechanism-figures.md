# 总览图与机制图：一次资源论文 Fig.1 + Fig.2 的定稿经验

整理于 2026-10-28。来源是一篇“agent 建库 + 资源 + 使用”论文的 Fig.1（总览）与 Fig.2（建库机制与核对）多轮重绘，作者最终认可。这里只记录可迁移的设计判断，不包含原项目的数据、图像、路径或数字；文中数字示例均为占位。与 [composition-from-approved-work.md](composition-from-approved-work.md) 和 [session-lessons.md](session-lessons.md) 互补。

## 1. 两张图的分工

| 图 | 只回答 | 不放 |
|---|---|---|
| 总览（Fig.1） | 系统怎么工作、产出了什么资源、怎么被使用 | 性能指标、准确率、通过率、置信区间 |
| 机制（Fig.2） | 每一层是怎么被核对的，核对结果是多少 | 再画一遍完整流程 |

- 作者原话的要求是“这个就纯粹说工作流的信息，量化指标都放 fig2”。总览图里任何“X% 通过”“95% CI”都应搬到机制图；总览图的空位用**流程本身**填（例如一个真实案例的逐轮运行记录），不用指标填。
- 搬走后要检查每个指标在后续图中仍有归宿；只有无处可去的才在机制图新增一行。
- 总览图的一个面板可以改为“资源本身”：例如打开一个真实发布样本，展示每个文件里有什么、每个值的出处。这比指标更像资源论文。

## 2. 灰色底框只表示“工作流的阶段”

- 统一一个中性灰底（如 `#f2f3f5`），只用于流程阶段（索引 / 标准化 / 发布，或 agent 示意图的分区）。
- 图表面板、案例故事板、准确率森林图**不加灰底**：用留白、细分隔线（0.5 pt 灰）和细描边的白卡片分组。作者的判断：“灰色背景框被滥用了”。
- 不要灰底里套白卡再套灰卡；嵌套最多一层。

## 3. 配色：去掉逐阶段粉彩

- 给每个阶段换一种浅色（蓝 / 薄荷 / 沙 / 淡紫）会被看成“AI 味”。对 14 篇 agent 论文 Fig.1 的调研结论一致：最好的图是白底 + 1–2 个有含义的强调色，颜色本身就是图例。
- 一套可用的语义分配：海军蓝 = agent 与“通过”；蓝 = 测序类数据；青 = 成像类数据；橙 = 失败 / 搁置；**砖红只用于人工审核**；紫 = 检索；其余灰。全文各图保持一致。
- 状态不用红绿；文字一律深色，颜色只在标记上。

## 4. 人在哪里：用结构和颜色表达，而不是漂浮的人像

- 漂浮的“研究者在桌前”小图标，以及竖直的整条“人工关口”色带，都被否决。
- 正确的表达是把**自动循环**与**人工复核**在结构上分开：
  - 循环（写脚本 → 沙箱运行 → 冻结评分器 → 失败返回）画在一个虚线框里，标注“自动循环，无人工”；
  - 出口写明“固定规则：全部检查通过才发布”；
  - 人工复核画在循环**之后**，“每个样本一次”，用砖红细边卡片，放真实被复核的图像。
- 若人工复核只覆盖某条路线，要在图上分开两条路线，避免暗示全部样本都经过同一个自动评分器。

## 5. 小图标

- 用扁平矢量小图标，不用 emoji 字形（PDF 中渲染不稳定，也会让文字审计报错）。可复用的实现见 [scripts/minicons.py](../scripts/minicons.py)：文件（h5ad / tif / json）、身份卡、压缩包、放大镜、眼睛、代码、终端、对勾、时钟、烧瓶、标尺、引号。
- 放在：阶段标题前、文件名前、工具名前、森林图的行组标题前、“缺失 / 未声明”这类状态前。每个面板 2–6 个，大小 20–34 单位（0.1 mm），与文字基线对齐。
- 解释性句子可以换成“图标 + 短标签”，但**原始输出要保留原文**（例如 agent 给出的拒绝记录：样本号、状态码、原因码、引用的 GEO 原文）。

## 6. 机制面板要画真实材料，把失败画在对象上

- 一个真实难例从头到尾：原始沉积（真实表格摘录）→ 第 1 次尝试被评分器拒绝（真实空间图 + 失败检查在检查环上标橙）→ agent 的**真实代码 diff**（− 橙，+ 蓝）→ 第 2 次尝试全部通过并发布。
- 腐化测试不要用小缩略图：在同一张真实点图上画出“原样 / 10% 交换 / y 翻转 / 基因标签错位”，每张下方写“哪项检查拦下，n/n”。
- **画之前先读运行日志。** 本次发现图注里写的修复动作（“引用了阵列间距、换算成 µm”）与日志不符：实际是保留同一读取器与网格坐标、只替换了两条无法核验的引文。一律以日志和发布清单为准，图、图注和论点文字一起改。

## 7. 图形要多样，但都要学术

- 被否决：同色柱状图反复出现、方块 / 华夫图、无坐标轴贴数字的条、斜率连线图、巨型数字。
- 可用：树图（类别面积）、比例圆（规模对比）、点 + Wilson 95% CI（比率）、环（一个整体的去向）、哑铃（同一样本的两个解释量）、2×2 混淆矩阵（判定 vs 真值）、带刻度轴的堆叠条（全部运行的结局）、箱线图（逐研究分布）。
- 条形只在有刻度的轴上；首次与末次的对比画成两个不连线的点或两个环。
- 口径写在图上或图注：分母、“UNSURE 记为未通过”、“覆盖率而非通过率”。

## 8. 趋势与不完整年份

- 用户要求“画到当年”时，曲线延伸到最后一年，但最后一段用虚线、终点用空心点，并标截止日期；不要外推或拟合补满。
- 份额（占当年全部记录的比例）比计数更适合跨年比较；各小图可用独立纵轴，但要在图注说明不可横向比较斜率。

## 9. 改版流程

- 作者说“丑 / 不直观”时，不要局部修补：出**三个概念不同**的方案（例如“一条流程带”“图像优先的故事板”“学术验证矩阵”），各自完整、同样过审计，并排给作者选。
- 可以让子代理并行各画一版（共享一份写明数据来源、风格和 QA 的简报），主代理逐一审阅、核对日志与数字，最终微调亲自做。
- 每轮请一位外部模型以“期刊编辑 + 审稿人 + 领域专家”身份提意见；只采纳与数据核对一致、且不违背作者已定决策的建议（例如被建议“删掉所有图标”时不采纳）。

## 10. 版面与质检

- A4 页面预留高度上限（例如 240 mm）。超高时先压缩空白、收紧行距、给拥挤的面板更多宽度，不缩字号；最小字号 5 pt。
- 每次渲染后：碰撞审计 0 fail / 0 warn（每个有意保留的 WARN 要说明），文字尺寸审计通过，再看 300 dpi 局部截图。
- 所有数字由脚本从源文件读取，不在绘图代码里手写；同名不同口径（例如“发布中出现的系列”与“按样本匹配交付的系列”）在图注里分别定义。

## 11. 过度声明检查清单

- 箭头是否暗示了并不存在的派生关系（例如“检索命中 → 全部训练样本”）？
- 图上的“再次看到”指的是主指标本身，还是包含它的更大指数？
- 是否有一部分样本走了另一条路线、并未经过图上画的检查？
- 修复动作、阈值、单位是否与运行日志一致？
