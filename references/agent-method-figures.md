# Agent 方法图：具体、紧凑、有信息量

用于把抽象 agent 架构或工作流改成读者能跟踪的方法图。与 [证据设计](evidence-design.md) 配合使用；这里专门处理对象、动作、工具和检查之间的视觉关系。设计案例的来源见 [范文模式](paper-patterns.md)。

## 让复杂度来自真实机制

按需要给一条关键路径补齐下列内容，不要求每项都成为独立 panel：

| 读者的问题 | 图内的具体表示 | 详细材料的位置 |
|---|---|---|
| 输入到底是什么？ | 真实图像/表预览、样本卡、矩阵、坐标场；简短身份标签 | 完整文件列表、下载版本、路径、哈希 |
| agent 根据什么做决定？ | 多源证据汇合、局部匹配、明确的判据/分支 | 完整 prompt、判断 schema、缺失情况 |
| 哪个工程能力使它做得到？ | 按功能分组的工具，连接到使用它的动作 | 函数签名、参数、包装器及实现 |
| 执行中发生什么？ | 短操作序列、程序/产物缩略图、返回观察、错误回路 | 命令全文、traceback、完整运行日志 |
| 怎样知道哪里错了？ | 实际中间图、被标记区域、检查状态、修订返回箭头 | 数学定义、阈值、回退策略和适用范围 |
| 最终保留什么？ | 同一身份的测量、位置、图像与来源记录 | 输出合同、完整结构及逐样本清单 |
| 方法是否真的有效？ | 对应案例、实验比较或独立审核 | 完整统计表、全部失败/未知、补充实验 |

一个有用的视觉单元是“具体对象 + 短动作 + 可见变化/判断”，而不是只写 `Analyze / Reflect / Improve`。例如用 ID 连线解释联结，用 x/y 十字线解释定位，用 footprint 与周围环解释局部背景检查。公开方法名、格式名和研究对象本身的接口可以出现；不熟悉项目代码的读者不该靠内部代号才能读懂。

## 连接线必须有语义

- 顺序箭头表示实际数据/控制流；相同样本的三个对象可以用分支连接，不能误画成“表达产生坐标，坐标产生组织图”。
- 工具库的共享连线表示可访问能力，不表示每个样本必须串行调用全部工具。并列判据可能在一次联合判断中使用，不自动意味着多个 agent 或独立 gates。
- 用短标签区分执行错误、诊断反馈和独立评价。虚线可以表示可选功能，但必须定义；不要为了复杂感随机混用实线、虚线和箭头。
- 只画实现支持的修订和终止条件。检查返回 warning 不等于强制失败，非阻断建议不能画成硬性验收闸门。
- 同一 agent 在构建和检查处重复出现时，用共同容器、连续回路或 `same agent` 等局部标记消除歧义。运行环境、质检工具、人审和独立 evaluator 保持各自角色。

## 工具充分、检查易用：把设计意图画出来

工具按操作能力组织，例如资产检索/读取、坐标或平台映射、身份联结、来源记录、图像观察和执行。每组用一两个可辨认对象及短动作承载；完整函数列表放在可追溯映射中。工具数量来自真实目录，并解释包装器/重复接口，不用数量冒充独立算法贡献。

若可操作的 QC 是方法主张，画出它如何嵌入修订循环：候选产物 → 可调用检查 → 状态/原因/定位图 → 有针对性的修订。可用性、运行速度和最终成功率是不同证据问题；未做相应测量时，写成设计目标，不画出凭空的提速或成功增益。

对图像质检，优先用实际显示中间图解释。以下仅是两种指标的视觉拆解示例，**只在选定实现确实这样计算时采用**：

- **Spillover：** 按表达选点 → 查看点覆盖区及周围环 → 标出均为空白的所选点 → 显示所选点中的空白比例。
- **Tissue spillout：** 图像估计组织区域，同时由测量点建立缓冲覆盖区 → 定位目标组织未被覆盖的部分 → 显示目标组织中的未覆盖比例。

前者以选中观察点计数，后者以目标组织面积计量，不能混用分母。目标组织如何选择、覆盖前提、阈值、极性与异常回退属于精确定义，应与冻结实现核对并放在图注/Methods。两条诊断可左右并排，不画成依次调用，也不把原始组织图假装成经过验证的分割真值。示意中间图不等于新增 benchmark 结果。

## 用信息密度解决空，不用文字量解决空

先找缺失的科学信息：对象身份、具体工具作用、中间状态、失效边界或独立证据。再把重复标题、重复图例、宽说明行和空白卡片合并。若证据没有缺口，适当缩短整图比加装饰更合理。

让机制区有一条显著主路径，再用局部分支补充细节。方法后续图需要比总览更深入，不需要重画整套输入—LLM—输出。一个主图可能采用：局部机制、真实案例、对应定量；资源规模可以另成紧凑结果图。图数和高度服从当前用户要求，不预设四图、不固定机制占比。

一个 lettered panel 可以包含两个相关坐标区或“图像对照 + 小 ROC”，各用轴名/对象名辨认，减少重复面板题头。扩大需要看细节的真实图像，缩小辅助曲线到仍能读轴与图例的尺寸。不要让三行实验背景挤掉半幅案例；必要背景可贴近对象或放图注。

对于全文：相同字体、语义色、线宽、图例顺序和比例尺形式构成统一；不要求所有图都使用同一排卡片。若相邻图删去标题后几乎相同，通常应重新明确各图承担的问题。

## 图标与原图的分工

机器人可作为 agent 的核心流程对象，使用与文件、工具、执行图标一致的平面细线轮廓；小幅微笑可以保留。不要为了“更多机器人”增加并不存在的角色，也不要把方法改成吉祥物宣传画。SVG 比系统 emoji 更容易保证字体和导出一致。

照片、组织、密集点场承担真实内容；图标用于快速识别角色/操作。选中点与十字定位线可以保持矢量，完整背景点场嵌入 PNG。保留所有观察点、坐标关系、像素尺度和图像语义颜色；详见 [混合导出](export-and-check.md#hybrid-vectorraster-figures)。

## 修订和范文核对

先定位认可基线和最新改动范围，再选择与该 panel 功能相同的原文面板对照。比较对象是否可辨、动作是否具体、文字层级、机制/证据面积和实际宽度下的密度，不只比较配色。

若要三套方案，改变叙事侧重才有意义：例如步骤/机制、案例/证据对应、职责/约束。排名说明读者理解成本、与其他主图的互补性、最终字号及证据保真，不给“创新感”造量化分数。若只改标签颜色或机器人表情，保留已认可布局及数据，验证导出即可。
