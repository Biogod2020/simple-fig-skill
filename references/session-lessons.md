# 这轮论文制图的作者偏好与返工经验

整理于 2026-09-15，来源是一次从初始图稿、多个重绘候选到正式写作图版的连续审阅。这里记录设计决策，不发布原项目的实验数据、图像、内部路径或完整对话。**稳定偏好可以沿用；具体图数、比例、图型和版本号必须服从当前任务。** 范文的可核对出处见 [paper-patterns.md](paper-patterns.md)。

## 1. 作者最终要的是什么

“专业 + 简洁美观”，同时“直观详细”“看上去复杂但是实际上很好理解”。其核心是**让真实方法的深度可见，让阅读路径简单**。不能用方框数量、字数、装饰或视觉噪声冒充创新性。

| 反复出现的要求 | 可执行的设计判断 |
|---|---|
| 学 NBME 的审美，当前稿先投 ICLR | 学具体论文的对象、线条、标注和机制/证据分工；最后在实际会议模板里检查，不称为 NBME 官方样式或质量认证。 |
| 读者是没读过文章/代码的编辑和审稿人 | 输入、动作、判据、输出要就地可辨。内部执行器代号、文件路径和项目缩写换成读者名称，代码映射留在追溯记录。公开标准名称和研究对象本身的接口名可以保留。 |
| 不要广告感、过强的“AI 味” | 白底、细线、克制的语义配色、暗色文字；少用大卡片、口号、徽章、巨型数字、发光渐变和立体效果。保留真实科学图像与常规统计图。 |
| 不要手绘风 | “人工粗糙”后来明确修正为专业简洁。不要抖线、涂鸦、纸张噪声、故意歪斜或随机不对齐；个性来自根据内容安排的版面。 |
| 文字太多不行，几乎无字也不行 | 短标题 + 对象名 + 短动作 + 必要数值/单位/判据。完整定义、条件、分母和限制放图注/Methods；关键解释紧贴图形，不另占几行副标题。 |
| 所有 panel 的文字都要对齐范文，特别不要浅灰 | 普通标题、节点、轴、刻度、图例、比例尺和局部说明统一深色。用字重、位置和字号分层，不用浅灰降低信息可见性。 |
| 密度还要高，但不能难读 | 加真实输入/输出、中间状态、工具能力、决策和失败回路、案例和实测证据；复用公共图例、压缩空白和说明行。不要靠缩小字体塞内容。 |
| 后续方法图不要重复 Fig.1 | 总览回答“系统做什么”；后续图分别回答局部机制“如何/为何有效”。只有新增问题、案例或验证才值得再展开流程。 |
| 表格减少，但不限定点图 | 比较、分布、组成、矩阵、空间对象分别选合适图形。保留有二维含义的矩阵；长数字查阅表移正式表/附录。图型多样性服从数据关系。 |
| 要可视化，不能只给文字建议 | 交付实际图件预览、可编辑源文件及代码。设计说明保持简洁，除非明确要求，不追加 HTML 对照网页。 |
| 参考范围扩大，至少 8/10 篇等 | 实质性重设计按当次要求检查足量相关原图，记录具体图号及借鉴点。不要只堆文献名字，也不要把这次数量变成每次改字的前置任务。 |

## 2. 方法图中最重要的补充

作者持续要求把 agent 的工程内容画实：可用工具、代码/程序、执行返回、质检、修订和独立审核之间有清楚的对象与连接。通用“输入 → LLM → 输出”不足以说明技术；完整内部函数清单也不是答案。

- 把工具按能力组织，让读者看到**工具能做什么、在哪个动作被使用、返回什么可检查结果**。检查文件可配放大镜，查看图像可配图框，工作流指导可配文档/手册图标。
- 把“工具充分、质检容易调用且能指导修订”作为工作流的核心设计意图。画出返回的状态、定位图和下一步动作；没有测量时不称为已证明的易用性、效率或成功率增益。
- 检验指标优先画成“对象/图像 → 操作 → 中间表示 → 待检区域 → 结果”的短流程。公式、阈值细则、回退条件放图注或方法。两条并列诊断不要误画成前后依赖。
- 全量人工审阅及其规模是有价值的证据，适合放在验证/资源区；必须说明审阅对象和标准，不能把视觉接受等同于所有源数据被完整认证。
- 机器人是作者后来认可的**核心角色图标**，不只是标题旁的小装饰。采用统一的细线 SVG，可有小幅微笑，连接真实输入、操作和反馈。同一个 agent 的多个动作不能被画成不存在的多 agent 系统。

具体画法与图内/图注分工见 [agent-method-figures.md](agent-method-figures.md)。

## 3. 这些是局部选择，不是永久规范

| 讨论中的变化 | 最终应如何理解 |
|---|---|
| 原有设计被改动过大，作者要求回到认可的 Fig.1 骨架 | 认可版是增量修改的起点；“更详细”不自动授权重新发明全部布局。 |
| 曾要求 A4 铺满并增加内容，后来要求页高停在 panel c 下方 | 先服从当次页面边界；A4 是审阅母版，不是必须填满的空格，也不是最终投稿尺寸。 |
| 流程曾要求不超过 2/5 高度，之后允许放大到原来的 1.5 倍 | 后来的明确放宽覆盖早期限制。保留密度并增加间距，不同时强行满足互相冲突的历史比例。 |
| 曾要求后续图细节是 Fig.1 两倍 | 表示需要更具体的局部方法深度，不按字数、节点数或面积声称“翻倍达标”。 |
| 从三张主图变成四张时作者提出异议，后来明确允许四张 | 不静默改变主图数量；必要时先说明新增图承担什么问题。允许四图后按新分工设计。 |
| 曾要求去掉扁长的底部 panel、并排 c/d、压缩资源图至一半 | 合并相关证据，按图内元素的最小可读尺寸重新分配空间；这些是指定图版的调整。 |
| 从点图改回“左边 SVG 图标 + 右边百分比 matrix” | 这是作者认可的来源证据表达，保留它。减少表格不等于禁止语义明确的矩阵。 |
| 组成长条改用饼/环图 | 适用于那组互斥组成，不推广到重叠覆盖率或精确方法差异比较。 |
| 灰色 XY 点阵不清楚，先提议热图，后选择十字定位线 + 高亮点 | 没有额外标量时无需热图。完整点场可栅格化，矢量十字线和选中点表达定位关系。 |
| 新增 AUC 后，作者要求保留原示例，再合并案例与小 ROC | 新指标不自动取代解释机制的真实案例。相关内容可共享一个 panel，减少重复标题与竖向说明。 |
| 曾要求三套候选并 rank，也曾要求 HTML 说服导师，后来明确“不用 HTML” | 这些交付形式按当次请求执行；不变成每次改图必须输出的三方案/网页套餐。 |
| v0.1、v0.2、v0.3……到 v1.0，之后稿件又有独立版本 | 图版和稿件版本分别登记。保留被接受的版本；新版明确基线、改动范围及当前入口。 |

## 4. 范文模式带来的可复用经验

1. **总览与局部机制分工。** Fig.1 提供地图，后续图解释一个具体机制并呈现对应证据，不反复画同一条大流程。
2. **抽象对象要接真实实例。** 表达矩阵、坐标、图像等对象用一致身份/颜色/引线相连，并有真实对象或中间表示让读者落地理解。
3. **工程细节应解释科学正确性。** 源身份、坐标变换、完整性和失效处理值得显示；缓存路径和内部日志字段通常不值得占据主图。
4. **机制与验证并置。** 方法小图配案例、对照、分布或失败边界，常比单独一整页架构更有说服力；机制图本身不证明效果。
5. **短语贴对象，细节进图注。** 避免图顶/图底一排排浅灰小说明；输入/输出名、操作和必要判据并不属于应该删除的“多余文字”。
6. **同一风格可以有多种图形。** 统一来自字体、线宽、间距、语义色和标注，而不是所有 panel 同形同尺寸。

上述是指定范文的设计归纳，不是统计过的领域使用频率，也不是 NBME/ICLR 的强制规定。

## 5. 每次修改前后最值得检查的事

修改前确定最新明确要求和认可基线；明确哪些 panel 的问题属于图形、文字、密度、语义或数据。小改动不重启全部文献阅读、实验与设计流程。

修改后在最终宽度检查：能否从输入读到输出，箭头是否有真实含义，关键文字是否足够暗且可读，图像/比例尺是否一致，案例与统计是否来自对应版本，失败/未知是否保留。对于全套图的修改，检查每一张，不只看刚改的 panel。

把密集点场/组织图作为合适分辨率的嵌入位图，保留标签和流程的矢量可编辑性；检查实际文件大小和打开效果。栅格化不代表删点、改坐标或重染原图。

交付放在统一 paper 入口：当前稿件、主图、图注、绘图代码、固定输入及来源映射。记录版本、哈希、已完成检查和限制。提交/推送按用户授权执行；设计范文只借组织方法，不混入原论文数据、图标或未实现能力。
